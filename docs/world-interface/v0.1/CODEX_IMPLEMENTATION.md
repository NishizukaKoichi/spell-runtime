# Codex implementation handoff — WIS v0.1

## 依頼

この資料群を仕様の出発点として、エージェントネイティブ・サービスの最小実装を作る。要約、計画、画面モックだけで完了にしない。まず既存リポジトリのAGENTS.md、構成、テスト、関連実装、作業中の差分を確認し、他の作業を壊さずに進める。

参照元は `NishizukaKoichi/spell-runtime` の `docs/world-interface-v0.1` ブランチ、`docs/world-interface/v0.1/`。開始時に実際に取得した40桁コミットSHAを実装記録へ残す。ブランチ名だけに依存して作業途中に仕様を追従・変更しない。ネットワークが使えない場合、資料が取得済みのチェックアウトを使う。取得できていないファイルを読んだことにしない。

ここに置いたことは、全機能をSpell Runtimeへ組み込めという指定ではない。既存の機能を調べ、再利用可能な部分と新規モジュールの境界を決める。特定技術への慣れではなく、人間の時間・操作・継続費用・保守・変更容易性の総合で技術を選ぶ。新しい基盤や別製品を必要なく増やさない。ユーザーの作業中ブランチを勝手に切り替えたり、mainを直接書き換えたりしない。

## 読むもの

この指示、SPEC-ja.md、schemas/wis.schema.json、openapi.json、examples/、tests/validate.pyを読む。既存テストを実行し、仕様本文とスキーマと例の不足・不一致を記録する。23テストの成功は構造と簡易モデルの確認にすぎず、認可・決済・永続性が実装済みという意味ではない。

仕様の目的と安全境界は維持する。一方、仮のデータ構造を完成品として盲従しない。実装に必要な補正は理由と受入試験を記録し、公開スナップショットを黙って別の意味へ変更しない。MCP等の採用版・API・安全条件は実装時に一次資料で確認して固定する。

## 最初の実物

本人側クライアント／実行基盤と、企業側の低リスクな提供サービスを作る。対象は合成データの非公開保存とする。サービスのManifestから能力を発見し、条件と入力を検証し、許可を確かめ、実際にデータを保存し、結果のダイジェストと公開範囲を検証してReceiptを返す。画面のクリックや人間によるコピー移動を必須にしない。

まずCoreの情報取得を動かし、次に限定されたActionを実装する。本人のUIは目的、進捗、お小遣い、エネルギー、例外、実行記録が分かる最小限にする。CLIやAPIから同じ機能を検証できるようにする。外観だけのデモを完成品にしない。

仕事の状態、操作ID、見積もり条件、残高の確保、Receiptを永続化し、プロセス再起動後も照合できるようにする。安全な区切りで停止し、補充と有効な権限に応じて再開する。停止できない外部処理まで止まったと表示しない。

お小遣いとエネルギーは独立した二つの資源として扱う。お小遣いが不足したら新しい有料工程だけを止める。エネルギーが不足したら新しい推論だけを止め、状態保存やイベント受領は続ける。片方の補充で他方や権限を勝手に増やさない。残高確保は並列処理でも二重使用できないようにする。

初版のお小遣いは模擬残高／決済テスト環境のみとする。本物のお金を預かる、購入する、継続契約する機能は有効化しない。エネルギーも実測が取れない場合はテスト用計測であると明示し、架空の数値を実際のモデル使用量やChatGPT利用残量として表示しない。ゲートウェイ接続のない部分は差し替え可能な境界を作る。

認可はモデルの文章で代用しない。開発用の信頼根を明示し、宛先、期限、対象、作用をコードで検証する。ローカル試験で簡略化した認証はローカル限定にし、公衆ネットワーク向けの本番OAuthと同等と主張しない。資格情報をリポジトリやログに書き込まない。外部送信先を制限し、外部データを新しい命令・権限と見なさない。

## 受入条件

一つの再現手順で「発見→条件確認→実行→結果検証」が実データの保存を伴って完了すること。同じ操作IDの再送で重複保存・重複精算を起こさず、異なる入力なら拒否すること。受理直後の通信断、プロセス再起動、実行結果不明を故障注入で試し、安全に照合・再開できること。

権限外の公開・削除、期限切れの権限、新規受付時の期限切れ見積もり、価格・条件のすり替え、未知の必須拡張を拒否すること。残高の並列確保、上限を超える精算、エネルギー不足、お小遣い不足、別々の補充と再開を試すこと。既に受理された契約を見積もり期限切れで勝手に値上げ・二重実行しないこと。

最初の一往復が動いた後、同じ能力を提供する二つ目のサービスと別のクライアント／検証ハーネスを用意し、提供者と利用側を差し替えて試す。同じコードの名前だけを変えたものを独立実装と呼ばない。未達の相互運用範囲は明記する。

最低限の手間の記録をローカルに残す。FrictionReportで不要な往復や人間への呼び戻しを観測できるようにするが、初版から無制限の自己改造や外部への自動報告はしない。

## 成果物と停止条件

動くコード、再現用README、起動・テストコマンド、正常系と異常系の結果、参照仕様のコミットSHA、設計判断、未実装項目を残す。既存プロジェクトの品質チェックも実行する。実行していないテストを合格と報告しない。

本番デプロイ、mainへのマージ、実課金、新規有料プラン、権限拡大、標準団体への提出は今回の実装指示に含めない。それらを要する箇所は無効化し、可能なローカル実装と検証を進め、最後に必要な人間の操作だけをまとめる。別の安全な工程が進められる限り、認証待ち一件のために全作業を停止しない。
